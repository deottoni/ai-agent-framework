Core Design Principles
Architecture
Modular & Swappable
Each component is independently replaceable. Change one module without affecting others — designed for rapid client customization.
assembly-driven→
Safety
Zero Hallucination Policy
Agent reads only from configured data. Never infer success from silence — explicit confirmation required for every tool invocation.

Scheduling Modes
realtime
Live Booking
Invokes book_appointment in-call. Only confirms with a valid confirmation_id returned by the tool.
request_only
Manual Queue
Never invokes booking tool. Collects fields and logs via create_note. Human team books manually afterward.
hybrid
Best Effort
Attempts realtime first. Falls back to request_only on any tool failure — seamless for the caller.
Pricing Modes
restricted
No Quotes
Never quote any price. Uses a redirect script to defer all pricing questions to the team.
open
Listed Prices
Quote only prices explicitly listed in the policy file. No estimates beyond what is documented.
contextual
Range Sharing
Share authorized price range if available. Otherwise fall back to the redirect script.

Tool Contracts

Formal behavioral contracts for all 7 standard tools. Every tool has a defined type, invocation sequence, confirmation requirement, and error handling path.

Standard Tool Invocation Pattern
1
Collect
Gather all fields
→
2
Confirm
Read back to caller
→
3
Invoke
Call the tool
→
4
Report
Inform caller of result
Tool Reference
Tool Name Type Returns Description
lookup_appointment Read-only appointment record Find existing appointment by name + phone. May be called silently.
book_appointment Side-effect confirmation_id Create new booking. Requires explicit caller confirmation. Only confirm with valid confirmation_id.
reschedule_appointment Side-effect updated_record Move appointment to new date/time. Requires existing appointment lookup first.
cancel_appointment Side-effect cancellation_status Cancel booking. May apply fee per policy. Offer reschedule before confirming cancellation.
create_note Side-effect note_id Log structured note for team follow-up. Primary fallback for all tool failures.
transfer_call Side-effect transfer_status Transfer to human agent or department. Used for escalation and emergency override.
send_confirmation Side-effect delivery_status Send SMS/email confirmation. Handles delivery failure — never assume success without status flag.
Error Handling Cascade
Step 1
Tool invocation fails → Attempt create_note to log caller info and issue. Promise team follow-up.
Step 2
create_note also fails → Attempt transfer_call to a human agent who can assist directly.
Step 3
transfer_call also fails → Read back caller info verbally. Provide fallback contact number. Apologize and end call gracefully.
